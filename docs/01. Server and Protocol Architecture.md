# 01. Server and Protocol Architecture

RhydaDB speaks the Cassandra Native Protocol v4 over TCP. The server layer owns
everything between the socket and the query engine: framing, version
negotiation, compression, per-connection session state, and request dispatch.

## Core Concepts

1. **Pipelined, thread-per-core when available** — on `tokio` (default) a single acceptor dispatches every `QUERY`/`EXECUTE` to its own task; on `monoio` `io_uring` (Linux, `RHYDADB_URING=1` + `--features uring`) `N = cpus` `FusionDriver` runtimes each own a `SO_REUSEPORT` listener and connection set — zero cross-thread wakeups on the hot path (`async_channel` for responses, `tokio::sync::Semaphore` with `sync` feature for per-conn inflight). In both modes a single reader task per connection parses frames back-to-back and requests on one connection execute concurrently; responses are written as they complete, possibly out of order. The CQL binary protocol correlates responses by stream id, exactly like Cassandra, so standard drivers work without modification. Throughput is decoupled from round-trip latency.
2. **Control plane stays ordered** — `STARTUP`, `OPTIONS`, `REGISTER`, `PREPARE` and plain-text `USE ...` queries execute inline on the reader task. This keeps hard ordering guarantees: a `PREPARE` is registered before any later `EXECUTE` of its id can arrive, and `USE` is applied before subsequent statements observe the session keyspace.
3. **Lock-free hot path** — per-connection shared state (`ConnShared`) uses fine-grained primitives: negotiated compression is an `AtomicU8`, the prepared-statement registry and session keyspace are `RwLock`s touched only by control-plane opcodes. `EXECUTE` never acquires a connection-level mutex.
4. **Backpressure** — in-flight requests per connection are capped by a semaphore (512); responses flow through a bounded channel (`tokio::sync::mpsc` on tokio, `async_channel` on monoio) into one writer task that coalesces into `write_vectored` / `write_all` (256 KB flush threshold).
5. **Single protocol version** — only `0x04` is accepted. Anything else is answered with an `Error` (0x000A) frame and the connection is closed.

## Components

### Frame Layer

- 9-byte header: `version | flags | stream (i16) | opcode (u8) | length (u32 BE)`.
- Response headers carry `version | 0x80` and echo the request stream id.
- Reads go through a 64 KB `BufReader`; writes are coalesced by a dedicated
  writer task that drains ready responses and issues one vectored write per
  batch (256 KB flush threshold).
- `TCP_NODELAY` is set on every socket. Frame length is capped at 64 MiB.

### Compression

- Negotiated during STARTUP via the `COMPRESSION` option: `lz4` or `snappy`
  (scylla-cql codecs).
- A compressed body arriving without negotiated compression is answered with
  an error; the connection stays alive.

### Request Dispatch

| Opcode | Handling |
|---|---|
| OPTIONS | `Supported`: CQL_VERSION 3.4.5, COMPRESSION lz4/snappy, PROTOCOL_VERSIONS 4 |
| STARTUP | negotiates compression, replies `Ready` (inline) |
| REGISTER | replies `Ready` (events are not emitted) |
| QUERY | dispatched to a task; runs through the query engine |
| PREPARE | parses, computes metadata, registers `id -> statement`, replies `Result` kind 0x0004 (inline) |
| EXECUTE | looks up the prepared id, decodes bind values, honors `skip_metadata`, dispatched to a task |
| BATCH | error 0x2200 (not supported) |
| AUTH_RESPONSE | error (authentication is disabled) |

### Write Completion Gating

Data writes are asynchronous inside the storage layer (see 03). Before a
response is sent for INSERT/UPDATE/DELETE/TRUNCATE/DROP, the server awaits the
write's completion ticket — strict read-your-writes with no worker thread ever
blocked. Metadata writes are synchronous inside the storage layer and need no
gating.

### Response Builders (protocol.rs)

- `ready`, `supported`, `error`, `result_void` (0x0001), `result_set_keyspace`
  (0x0003), `result_schema_change` (0x0005), `result_prepared` (0x0004),
  `result_rows` (0x0002).
- Rows metadata: flags, column count, keyspace/table, per-column name + type.
  With `skip_metadata` the metadata block is replaced by `columns_count = -1`.
- Prepared metadata: bind specs in statement order, partition-key positions,
  and result column specs for SELECT.

### Error Codes

| Code | Meaning |
|---|---|
| 0x0000 | internal error |
| 0x000A | protocol error / malformed frame |
| 0x2000 | syntax error |
| 0x2200 | invalid request / unprepared statement |
| 0x2400 | already exists |
