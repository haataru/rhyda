# 01. Server and Protocol Architecture

RhydaDB speaks the Cassandra Native Protocol v4 over TCP. The server layer owns everything between the socket and the query engine: framing, version negotiation, compression, per-connection session state, and request dispatch.

## Core Concepts

1. **One task per connection** — `server::run` accepts sockets in a loop and spawns a tokio task per connection. Network I/O never blocks the database.
2. **Synchronous request/response** — each connection reads a 9-byte header, reads the body, executes the request, writes one response, then reads the next frame.
3. **Session state per connection** — keyspace, negotiated compression, and the prepared-statement registry live in `ConnState`; connections are fully isolated.
4. **Single protocol version** — only version `0x04` is accepted. Anything else is answered with `Error` (0x000A) and the connection is closed.

## Components

### Frame Layer

- 9-byte header: `version | flags | stream (i16) | opcode (u8) | length (u32 BE)`.
- Response headers carry `version | 0x80` and echo the request stream id.
- Bodies are compressed when flag `0x01` is set; frame length is capped at 64 MiB (`MAX_FRAME_LENGTH`).

### Compression

- Negotiated during STARTUP via the `COMPRESSION` option: `lz4` or `snappy` (scylla-cql codecs).
- A compressed body arriving without negotiated compression is answered with an error; the connection stays alive.

### Request Dispatch

| Opcode | Handling |
|---|---|
| OPTIONS | `Supported`: CQL_VERSION 3.4.5, COMPRESSION lz4/snappy, PROTOCOL_VERSIONS 4 |
| STARTUP | negotiates compression, replies `Ready` |
| REGISTER | replies `Ready` (events are not emitted) |
| QUERY | decodes query text + values, runs through the query engine |
| PREPARE | parses, computes metadata, registers `id -> statement`, replies `Result` (kind 0x0004) |
| EXECUTE | looks up the prepared id, decodes bind values, honors `skip_metadata` |
| BATCH | error 0x2200 (not supported) |
| AUTH_RESPONSE | error (authentication is disabled) |

### Response Builders (protocol.rs)

- `ready`, `supported`, `error`, `result_void` (0x0001), `result_set_keyspace` (0x0003), `result_schema_change` (0x0005), `result_prepared` (0x0004), `result_rows` (0x0002).
- Rows metadata: flags, column count, keyspace/table, per-column name + type. With `skip_metadata` the metadata block is replaced by `columns_count = -1`.
- Prepared metadata: bind specs in statement order, partition-key positions, and result column specs for SELECT.

### Error Codes

| Code | Meaning |
|---|---|
| 0x0000 | internal error |
| 0x000A | protocol error / malformed frame |
| 0x2000 | syntax error |
| 0x2200 | invalid request / unprepared statement |
| 0x2400 | already exists |
