# 02. Query Engine Architecture

The query engine turns CQL text (or a prepared statement) into a `Response`
plus a list of write-completion tickets. It parses with the tree-sitter CQL
grammar, validates against the schema cache, and executes reads and writes
against the sharded storage layer (see 03).

## Core Concepts

1. **Parse once, reuse** — parsed statements are cached by exact query text in
   a bounded AST cache (8192 entries, cleared wholesale on overflow). The hot
   path is an `Arc` clone.
2. **Raw bind values** — QUERY-with-values and EXECUTE both deliver untyped
   wire bytes (`RawValue`) into `Binds`, which decodes lazily using the column
   type from the schema.
3. **Schema-driven execution** — every statement resolves keyspace/table
   against the schema cache (`Arc<TableDef>`, zero-copy reads); identifiers
   are matched ASCII-case-insensitively for plain names, verbatim for quoted
   ones — without allocating on the hot path.
4. **System keyspaces are read-only** — `system` and `system_schema` reject
   all writes.

## Statement Dispatcher

`execute_statement` matches on statement kind: USE, CREATE/DROP KEYSPACE,
CREATE/DROP TABLE, INSERT, SELECT, DELETE, UPDATE, TRUNCATE. Anything else ->
invalid request (0x2200).

Write statements return completion tickets alongside the response; the server
awaits them before acknowledging (see 01). Read statements return none.

## Binds

- `Binds::none` for plain QUERY, `Binds::new` when values are present;
  out-of-bounds or malformed values are rejected.
- Values decode per column type (`Value::from_raw_bytes`); literal operands
  parse via `Value::parse_literal`.
- Collections (set/list/map) accept literal elements; bind markers bind whole
  collection values.

## Prepared Statements

- `prepared_info` computes bind specs in wire order:
  - INSERT — column order, with partition/clustering key positions reported
    via `pk_indexes`;
  - UPDATE — assignments first, then WHERE params;
  - SELECT / DELETE — WHERE params only;
  - SELECT also reports result column specs.
- PREPARE stores `id (u16, wrapping) -> statement + bind types` per
  connection; EXECUTE with a missing id returns 0x2200 (unprepared).

## SELECT Execution

Plans in three tiers:

1. **Point lookup** — when every partition-key AND clustering-key column is
   restricted by `=`, the row address is fully known: one direct `get` on the
   owning engine. No iterator is involved. For the common single-PK `EQ`-only
   case (e.g. `bench.kv` `SELECT * WHERE id=?`) a **fast path** (`project_fast_point`) builds the output row by scanning the sparse `value_bytes` only for the `selected` indexes, without allocating the full `Vec<Value>` row vector or re-checking PK filters.
2. **Partition scan** — when all partition-key columns are restricted (some
   via `IN`), each cartesian combination of partition values streams its
   partition from the owning engine with early termination at `LIMIT`.
3. **Table scan** — otherwise every engine is streamed sequentially
   (unordered across engines, as CQL permits).

Generic path precomputes `selected_idxs` / `eq_filters` / `in_filters` / `key_col_idxs` once per `SELECT` to avoid per-row `column_index` linear searches inside `project_decoded`/`handle_entry` (critical for scans). Filters not pushed into the key (e.g. non-key columns) are re-checked after row reconstruction; `LIMIT` stops the stream without materializing remaining rows. `Value::write_wire` and `encode_row_columns` are zero-copy (direct `extend_from_slice` into the response buffer, no intermediate `Vec<u8>` per value); `protocol::result_rows` pre-reserves `rows.len() * 16` bytes.

## Write Paths

- **INSERT** resolves every provided column straight to its index (no string
  maps), builds key parts + sparse column payload, and enqueues one put.
- **UPDATE** is read-modify-write to preserve merge semantics, except when
  assignments cover *all* regular columns — then it degrades to a pure upsert
  with no read.
- **DELETE** requires the full primary key (partition + clustering) and issues
  one tombstone.
- **TRUNCATE / DROP** enqueue range tombstones through the write pipelines so
  they can never overtake queued row ops (see 03).

## DDL & Schema Mirror

- DDL persists `KeyspaceDef` / `TableDef` and mirrors metadata into
  `system_schema` rows (`keyspaces`, `tables`, `columns`) using the
  synchronous path — immediately visible, independent of data pipelines;
  drops mirror the removal.
- `system.local` is seeded at startup (Murmur3Partitioner, CQL 3.4.5, host
  UUID) so drivers that probe it work out of the box.

## Type System (schema.rs)

Wire type ids (protocol v4): int 0x0009, bigint 0x0002, smallint 0x0013,
tinyint 0x0014, float 0x0008, double 0x0007, boolean 0x0004, text 0x000D,
blob 0x0003, timestamp 0x000B, uuid 0x000C, inet 0x0010, set 0x0022,
list 0x0020, map 0x0021. `text`/`varchar`/`ascii` and `uuid`/`timeuuid` map
onto the same storage types.
