# 02. Query Engine Architecture

The query engine turns CQL text (or a prepared statement) into a `Response`. It parses with the tree-sitter CQL grammar, validates against the schema cache, and executes reads and writes against `Storage`.

## Core Concepts

1. **Parse once, reuse** — parsed statements are cached by exact query text in a bounded AST cache (8192 entries, cleared wholesale on overflow).
2. **Raw bind values** — QUERY-with-values and EXECUTE both deliver untyped wire bytes (`RawValue`) into `Binds`, which decodes lazily using the column type from the schema (`take(ColumnType)`).
3. **Schema-driven execution** — every statement resolves keyspace/table against the schema cache; identifiers are normalized (`norm_id`: quoted verbatim, unquoted lowercased).
4. **System keyspaces are read-only** — `system` and `system_schema` reject all writes.

## Components

### Parser & AST Cache

- `cql3-parser` over a vendored fork of `tree-sitter-cql` that accepts bind markers (`?`) in UPDATE assignment values (upstream grammar only allows literals there).
- `parse_cached`: cache hit returns `Arc<CassandraStatement>`; a miss parses, and a grammar error becomes a syntax error (0x2000).

### Statement Dispatcher

`execute_statement` matches on statement kind: USE, CREATE/DROP KEYSPACE, CREATE/DROP TABLE, INSERT, SELECT, DELETE, UPDATE, TRUNCATE. Anything else -> invalid request (0x2200).

### Binds

- `Binds::none` for plain QUERY, `Binds::new` when values are present; out-of-bounds or malformed values are rejected.
- Values decode per column type (`Value::from_raw_bytes`); literal operands parse via `Value::parse_literal`.
- Collections (set/list/map) accept literal elements and nested binds.

### Prepared Statements

- `prepared_info` computes bind specs in wire order:
  - INSERT — column order, with partition/clustering key positions reported via `pk_indexes`;
  - UPDATE — assignments first, then WHERE params;
  - SELECT / DELETE — WHERE params only;
  - SELECT also reports result column specs.
- PREPARE stores `id (u16, wrapping) -> statement + bind types` in `ConnState`; EXECUTE with a missing id returns 0x2200 (unprepared).

### SELECT Execution

- Column list: `*` expands to all table columns; named columns (aliases allowed); functions are rejected.
- Filters: `=` and `IN` only; values are literals or binds.
- Key-restricted plan: when every partition-key column is restricted, `scan_partition` runs per cartesian combination of IN lists; otherwise the full table is scanned (`scan_rows`).
- Rows are reconstructed from key parts plus sparse column values, filters are re-checked in a post-pass, and `LIMIT` is honored.

### DDL & Schema Mirror

- DDL persists `KeyspaceDef` / `TableDef` and mirrors metadata into `system_schema` rows (`keyspaces`, `tables`, `columns`); drops mirror the removal.
- `system.local` is seeded at startup (Murmur3Partitioner, CQL 3.4.5, host UUID) so drivers that probe it work out of the box.

### Type System (schema.rs)

Wire type ids (protocol v4): int 0x0009, bigint 0x0002, smallint 0x0013, tinyint 0x0014, float 0x0008, double 0x0007, boolean 0x0004, text 0x000D, blob 0x0003, timestamp 0x000B, uuid 0x000C, inet 0x0010, set 0x0022, list 0x0020, map 0x0021. `text`/`varchar`/`ascii` and `uuid`/`timeuuid` map onto the same storage types.
