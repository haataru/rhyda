# 03. Storage Engine Architecture

A single RocksDB instance backs the whole database. The storage layer owns the on-disk layout, the schema and AST caches, and the write pipeline, and exposes a small synchronous API used by the query engine.

## Core Concepts

1. **Three key namespaces** — `ks!` for keyspace metadata, `tb!` for table definitions, `dt!` for row data; all keys are lexicographically ordered byte strings.
2. **Single writer thread** — every mutation goes through an mpsc channel into the `rhydadb-writer` thread, which coalesces up to 512 operations into one `WriteBatch` — one fsync per batch in durable mode.
3. **Read-your-writes** — reads flush pending batches through a sequence-number barrier before touching the database.
4. **Caches for hot paths** — schema caches (RwLock) and the AST cache (Mutex) avoid deserialization and re-parsing on every request.

## Components

### Key Layout

- `ks!<name>` — `KeyspaceDef` serialized as JSON.
- `tb!<keyspace>!<table>` — `TableDef` serialized as JSON.
- `dt!<keyspace>!<table>!<pk1>...` — row data. Key parts are length-prefixed (`u16 BE` + bytes, `encode_key`); `decode_key` reverses them.
- Row values are sparse: `[idx u16 BE][wire value]` per non-null regular column (`encode_row_columns` / `decode_row_columns`); a length of `-1` marks null. Partition and clustering key columns live only in the key, not in the value.

### Write Pipeline

- `put` / `delete` increment `sent_seq` and send a `WriteOp`; `writer_loop` batches up to 512 ops (`MAX_BATCH_OPS`) and calls `db.write_opt(batch, wopts)`.
- The writer's `WriteOptions` get `sync = true` when `RHYDADB_SYNC` is set — fsync per batch instead of per operation.
- Barrier: a `flushed` counter plus condvar; `flush()` waits until `flushed >= sent_seq` (100 ms timeout), which gives readers a consistent view of all writes accepted so far.

### Read Path

- `get` / `scan_prefix` flush pending writes first, then read from RocksDB (memtable + SSTs); prefix scans iterate forward and stop at the first non-matching key.
- `delete_prefix` (used by TRUNCATE, DROP) scans the prefix and deletes each key.

### Schema Cache

- `RwLock<HashMap>` over keyspaces and tables: reads hit the cache, a miss performs one RocksDB read plus JSON deserialization and fills the cache.
- DDL updates both RocksDB and the cache; DROP evicts the affected entries. The AST cache (see 02) is owned here and invalidated wholesale at capacity.

### Group Commit Effect

Batching writes turns per-op fsyncs into one per batch. Measured on a dev box (16 clients x 2500 iterations, fsync mode):

| Query shape | Before | After |
|---|---|---|
| INSERT | ~20.8k RPS | ~98.6k RPS |
| PREPARED INSERT | ~17k RPS | ~115k RPS |

No-sync mode sustains ~110-115k RPS across INSERT/SELECT with any query shape (raw, prepared, or cached-parse).
