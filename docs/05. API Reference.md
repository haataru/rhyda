# 05. API Reference

RhydaDB speaks the **Cassandra Native Protocol v4** on TCP (default
`127.0.0.1:9042`). Any driver that speaks protocol v4 works — the examples use
the official Python `cassandra-driver`.

## Connection

```python
from cassandra.cluster import Cluster

cluster = Cluster(["127.0.0.1"], protocol_version=4)
session = cluster.connect()
```

| Aspect | Behavior |
|---|---|
| Protocol versions | v4 only; other versions are rejected |
| Compression | `lz4`, `snappy` negotiated via STARTUP |
| Prepared statements | fully supported, incl. `skip_metadata` result sets |
| Paging | not implemented; `page_size` is ignored and full result sets are returned |
| Batches | not supported (`BATCH` returns an error) |
| Events / REGISTER | acknowledged, no events emitted |
| Authentication | disabled; TLS terminated outside (e.g. stunnel) if needed |
| Consistency levels | parsed and ignored — single node |

## CQL Surface

### Keyspaces

```sql
CREATE KEYSPACE shop WITH replication = {'class': 'SimpleStrategy', 'replication_factor': 1};
USE shop;
DROP KEYSPACE shop;
```

- `IF NOT EXISTS` / `IF EXISTS` supported.
- The replication map is stored and reported to drivers but has **no runtime
  effect** — RhydaDB is single-node.

### Tables

```sql
CREATE TABLE users (
    id int,
    org uuid,
    name text,
    tags set<text>,
    attrs map<text, text>,
    PRIMARY KEY ((org), id)          -- partition keys, then clustering keys
);
DROP TABLE users;
TRUNCATE users;
```

- Compound partition keys and clustering keys are supported.
- `ALTER TABLE` is not supported.

### Writing

```sql
INSERT INTO users (org, id, name, tags) VALUES (?, ?, ?, ?);
UPDATE users SET name = ? WHERE org = ? AND id = ?;
DELETE FROM users WHERE org = ? AND id = ?;
```

- Bind markers (`?`) work everywhere values do, including UPDATE assignments.
- INSERT is an upsert. UPDATE merges into the existing row (read-modify-write)
  unless every regular column is assigned — then it is a pure upsert.
- Collection columns (`set`/`list`/`map`) are replaced wholesale; partial
  collection updates are not supported.
- DELETE requires the full primary key; column-level deletes are not
  supported.

### Reading

```sql
SELECT * FROM users WHERE org = ?;
SELECT id, name FROM users WHERE org = ? AND id = 42;
SELECT * FROM users WHERE org IN (?, ?) LIMIT 100;
SELECT * FROM users;                       -- full scan, unordered
```

- Restrictions: `=` and `IN` on any column; non-key restrictions are applied
  as a post-filter after a scan (permissive — real Cassandra would reject some
  of these).
- `LIMIT` stops row streaming early; point lookups never allocate iterators.
- Aggregations, functions in SELECT, ORDER BY, ALLOW FILTERING semantics,
  TTLs, counters, secondary indexes and materialized views are not supported.

## Data Types

| CQL type | Notes |
|---|---|
| `int`, `smallint`, `tinyint`, `bigint` | big-endian wire encoding |
| `float`, `double` | IEEE 754 |
| `boolean` | |
| `text`, `varchar`, `ascii` | UTF-8 |
| `blob` | opaque bytes |
| `timestamp` | epoch milliseconds |
| `uuid`, `timeuuid` | 16 bytes, same storage type |
| `inet` | IPv4/IPv6 |
| `set<T>`, `list<T>`, `map<K,V>` | replaced wholesale on write |

## System Tables

Standard driver-facing mirrors are maintained:

- `system.local`, `system.peers`
- `system_schema.keyspaces`, `system_schema.tables`,
  `system_schema.columns`, plus empty stubs for `indexes`, `triggers`,
  `types`, `functions`, `aggregates`, `views`.

Writes to `system` / `system_schema` are rejected.

## Configuration (environment variables)

| Variable | Default | Meaning |
|---|---|---|
| `RHYDADB_DATA` | `./data` | Data directory (do NOT put it inside synced/antivirus-scanned folders) |
| `RHYDADB_LISTEN` | `127.0.0.1:9042` | Bind address |
| `RHYDADB_SYNC` | unset | Durable mode: fsync group-commit for data writes |
| `RHYDADB_ENGINE_SHARDS` | `min(cpus, 8)` | Independent RocksDB instances, 1–64; persisted on first start |
| `RHYDADB_CACHE_MB` | `1024` | Shared RocksDB block cache |
| `RHYDADB_MEMTABLE_MB` | `128` | Per-engine memtable size |
| `RHYDADB_MANUAL_WAL` | unset | Opt-in manual WAL buffering (non-durable mode) |

## Error Codes

Protocol-standard codes are returned: `0x0000` internal, `0x000A` protocol,
`0x2000` syntax, `0x2200` invalid/unprepared, `0x2400` already exists.

## Not Production-Hardened (honest list)

- Single node: no replication, no multi-node anything.
- No authentication, no TLS.
- No TTL / counters / LWT / BATCH / paging / ALTER TABLE.
- Test suite covers protocol correctness, concurrency and restart persistence;
  it is small by database standards.
